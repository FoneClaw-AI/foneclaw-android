# FoneClaw 0.3.7

## What’s new

- Choose from five animated pet companions: duck, dog, dragon, rabbit and deer. Set a name and an independent reply style in Assistant settings, with a refreshed startup guide in direct-distribution builds. Animations are bundled for local playback.
- Start with a personalized first greeting and find clearer Ask entry points in built-in workspaces. The first greeting is local, not an unsolicited model request, and is not backfilled to installations that already completed onboarding.
- Read streamed replies, reasoning and news tables with more consistent formatting and less exposed tool-protocol text.
- Ask in chat to change a news task between quick summaries and standard research, with confirmation before saving. Quick summaries use one search without opening articles, trading depth and coverage for a smaller research scope.
- Get improved article-body extraction and clearer search-failure handling, subject to source access and available services.
- Open task records more reliably. Removing an active news report also requests cancellation of that exact execution without deleting task history. Cancellation is a request, not proof that background cleanup has finished.
- Retry failed voice-memo summaries or chapters with clearer progress. Deleting multiple travel drafts cancels their pending generation before removing them.

## Availability and limits

- Companion appearance and reply style do not change tool permissions or approval rules. Bundled animation is not offline AI, automatic pet progression or unlimited memory.
- News presets remain disabled by default. Existing memory controls and task-result notifications are not a newly delivered memory-driven recommendation or proactive-companion notification service.
- Existing text and public-link sharing for eligible conversations and structured news remain subject to content eligibility, configured publication services and applicable review. Publication creation and its worker default to disabled with runtime controls, and guest access is separately gated. Public-page Listen, Report and Subscribe actions are download guidance, not browser playback, report submission or subscription creation.
- Search, voice and model-backed work require network access, account eligibility, permissions and enabled services. Cloud/local web-reading fallback is not offline search and does not bypass authentication. Online-model endpoints still require HTTPS.
- Travel draft cleanup is available through the existing workflow. New backend travel queries and provider configuration do not establish Android integration or production availability: current in-app travel research still uses web research. City, weather and scenic-provider work requires deployment, configuration, access and quota gates. Development acceptance does not prove production rollout. Flights, trains, ticket offers and route matrices are not presented as complete bookable services.

## Channel scope

- FoneClaw direct builds include online and offline speech variants. Offline synthesis does not make online features offline. Direct-only floating controls and external Android APK plugins remain subject to permission and runtime gates.
- Google keeps its legacy startup guide, with companion selection in Assistant settings. It includes the shared companion, news, task, Message Center and recording flows, not direct-only floating controls or external Android APK plugin execution. Its dedicated backend travel APIs reject the Google channel. Google Play submission, review and availability are separate from APK distribution.
- CN uses independent domestic services and updates with no Firebase or FCM token provider. It retains shared built-in workflows and web-research fallback. Plugin repository access remains network-dependent.
- Backend source delivery is not production deployment. No seamless process-restart recovery, device-acceptance result or unconditional service availability is asserted. Lebest remains discontinued.
